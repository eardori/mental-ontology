## 30초 요약 / What this is

**이건 앱이 아니라 [Claude Code](https://claude.com/claude-code) 스킬 하나입니다.**
`skills/mental-ontology/`를 `~/.claude/skills/`에 복사하면, Claude Code에게 한국어(또는 영어)로
말하는 것만으로 아래가 돌아갑니다. 서버도, 계정도, 외부 전송도 없습니다 — **전부 내 컴퓨터 안**.

```
🎙 녹음(Plaud/오디오) → 전사 → 화자 식별(목소리 지문·캘린더) → 회의록 코퍼스(마크다운)
                                                      ↓
                                    온톨로지 = 사람들의 사고·의도·관계 지도
                                                      ↓
        🔔 먼저 말해주기        ❓ 물어보기            📊 보기            🧭 전략 뽑기
        (놓친 것 브리핑)      (SQLite + 전문검색)   (HTML 뷰어·도시에)   (워크플로우 5종)
```

**핵심 설계 원칙 세 가지** — 이 리포를 복사해 쓰신다면 이것만은 알고 쓰세요:

1. **지어내지 않습니다.** 근거 등급이 계산으로 정해지고(반복 관찰이 `high`를 *획득*),
   인용문은 실제 발화에 접지 검증되며, 의도 추정은 **적중률을 공개**합니다.
   틀린 걸 숨기는 순간 이런 도구는 쓸모가 없어집니다.
2. **로컬 우선.** 코퍼스·DB·목소리 지문·캘린더 캐시 전부 내 폴더에만. 외부 전송 없음.
3. **사적인 판단 보조 도구입니다.** 남을 평가하는 리포트가 아니라, 내가 놓친 걸 나만 보는 것.
   ("분석당한다"는 인상을 주지 않기 — 방법론 원안자의 조언)

버전별 변화는 [CHANGELOG.md](./CHANGELOG.md)에 있습니다. 지금은 **v2.0** —
"묻는 도구"에서 **"먼저 말해주는 도구"** 로 넘어온 버전입니다.

## 🏁 3분 퀵스타트 / Quickstart

설치 후 Claude Code에서 순서대로 말해보세요:

1. **"최근 Plaud 녹음 가져와서 정리해줘"** — 녹음을 가져와 화자를 확인하며 회의록 코퍼스를 만들고, **정리가 끝나면 '놓친 것 브리핑'이 바로 나옵니다.** (첫 실행 시 코퍼스 위치를 물어봅니다 — Obsidian 볼트 추천)
2. **"온톨로지 분석해줘"** — 사고방식·의도·관계 지도 + 뷰어 + 인물 도시에가 생성됩니다.
3. **"X는 어떻게 생각하는 사람이야?"** / **"내일 ○○ 만나"** — 이제 데이터가 답하고, 먼저 말합니다.

> 💡 **쓸수록 조용해집니다.** 목소리 지문·화자 별칭·캘린더가 쌓이면 질문이 줄고,
> 회의가 쌓이면 사람들의 생각이 어떻게 **변했는지**까지 보입니다.

## 🔔 먼저 말해주기 (Push) — 묻지 않아도 놓친 걸 알려줍니다

**놓친 건 물어볼 수가 없습니다.** 그래서 녹음을 정리하고 나면 브리핑이 먼저 나옵니다 —
전부 DB에서 **계산된 것**이라 지어낼 수가 없습니다 (`build_briefing.py`):

| 언제 | 명령 | 나오는 것 |
| --- | --- | --- |
| **회의 직후** | "방금 회의 정리해줘" | 내가 한 약속 · 상대가 원한 것(추정+신호) · 답 없이 지나간 대목 · 발화 비중과 질문 수 · 참석자와의 미이행 약속 · 처음 만난 사람 |
| **만나기 전 30초** | "내일 〈이름〉 만나" | ⚡내가 아직 안 한 것 → 확인할 추정 → 이 사람과 일하는 법 → 충돌 축의 공유 공리 → 개인 맥락(△/⛔) → 최근 접촉 |
| **내일 일정** | "내일 일정 브리핑해줘" | 캘린더의 내일 일정마다 만날 사람의 ⚡미이행 약속 · 확인할 추정 · 마지막 접촉 |
| **주 1회** | "이번 주 정리해줘" | 오래 열린 약속 · 확인 안 된 추정 + 적중률 · 조용해진 관계(45일+) · 새로 만난 사람 |

> 발화 비중에는 **화자 미상 비율**이 항상 같이 나옵니다. 60%만 식별된 회의의 점유율은
> 숫자로 거짓말을 하는 것이라서요.

## 📊 모은 데이터로 할 수 있는 3가지 / Three things you can do with the data

### ① 보기 (View) — 사고방식 지도

분석이 끝나면 **어떻게 볼지 스킬이 물어봅니다** — 원하는 형태로 골라 받으세요 (전부도 가능):

| 형식                     | 파일                   | 이럴 때                                                                                                      |
| ------------------------ | ---------------------- | ------------------------------------------------------------------------------------------------------------ |
| **인터랙티브 HTML 뷰어** | `_ontology/index.html` | 더블클릭 한 번으로 전체 지도 탐색 (모델·관계 그래프·시간축 + **충돌 축·함정 지도**)                          |
| **md 종합 리포트**       | `_ontology/REPORT.md`  | Obsidian/Notion에 넣고 읽는 내러티브 보고서                                                                  |
| **인물 도시에**          | `people/이름.md`       | 한 사람의 모든 것 — 접촉 이력·개인 맥락·사고방식·관계·수기 메모(재생성해도 보존). 1:1 전, 위임 전, 피칭 전에 |

#### v3–v4 — 빛만이 아니라 그림자까지, 그리고 말 뒤의 의도까지

대부분의 "인물 분석"은 장점 목록에서 멈춥니다. 이 온톨로지는 다섯 가지를 더 그립니다:

|     | 무엇                        | 왜 강력한가                                                                                                                                               |
| --- | --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 🕳   | **함정 지도 (Trap Map)**    | 각 사고방식이 만들어내는 **부작용**과 그 상태(미해결→자각 중→해소됨). 강점의 그림자를 추적해야 위임과 자기교정이 가능해집니다                             |
| ⚔️  | **충돌 축 (Conflict Axes)** | 두 사람의 갈등을 "대립"으로 끝내지 않고 **공유하는 공리 + 대칭으로 갈리는 실행**으로 그립니다. 갈등 해소의 출발점은 언제나 공통 지반입니다                |
| 🎯  | **개입 문법 (Playbook)**    | 인물마다 "이 사람과 일할 때/설득할 때" 운영 지침 — 1:1 전 30초 브리핑                                                                                     |
| 💭  | **대화 의도 (Readings)**    | "저 사람이 나한테 원한 게 뭐였지?" — 반복·무응답·화제전환·마무리발언 같은 **텍스트 신호가 있을 때만** 기록하는 회의별 의도 추정. 실제 발언과 신호를 항상 함께 보여주고, 나중 회의에서 ✅확인/❌빗나감으로 정산해 **적중률**을 공개합니다 (틀린 걸 숨기지 않는 게 이 층의 신뢰 조건) |
| 🔍  | **근거 3분법**              | 본인 발화(direct) / 타인의 전언·해석(hearsay) / 언급만(reference)을 구분 표기 — **남이 그 사람에 대해 말한 것을 그 사람의 생각으로 착각하지 않게** 합니다 |

> `viewer.html`을 그냥 더블클릭해 보세요 — 가상 스타트업 Acme의 가격 인상 논쟁이 충돌 축·함정 지도까지 채워진 상태로 렌더링됩니다. CEO와 CPO가 싸우는 게 아니라 **같은 공리(LTV) 위에서 순서만 다투고 있다**는 걸 30초 만에 보게 됩니다.

### ② 묻기 (Ask) — 회의 전체가 검색 가능한 DB가 됩니다

온톨로지가 갱신될 때마다 **SQLite DB**(`_ontology/ontology.db`)가 만들어집니다 — 모든 회의·발화(전문 검색)·인물·모델·관계·시간축이 테이블로. Claude에게 자연어로 물으면 DB를 조회해 **날짜·실제 발언을 인용하며** 답합니다:

```
"정우진 대표는 어떤 사람이야? 뭘 중요하게 생각해?"
"이 프로젝트, 이서연 님한테 맡겨도 될까?"
"내일 ○○ 대표랑 미팅인데 준비 브리핑 만들어줘"
"우리 조직에서 지금 어디가 안 맞아?"
"'정산' 얘기가 나온 회의 전부 시간순으로 정리해줘"
"어제 미팅에서 내가 놓친 거 있어? 저 사람이 진짜 원한 게 뭐야?"
"지난 분기 동안 내 생각은 어떻게 변했어?"
```

### ③ 구상하기 (Strategize) — 회의 데이터에서 사업과 전략을 뽑아냅니다

`PLAYBOOK.md`의 구조화된 워크플로우 5종 — 각각 **문서 산출물**을 만들어 `_strategy/` 폴더에 쌓습니다:

| 워크플로우             | 이렇게 말하세요                         | 산출물                                                   |
| ---------------------- | --------------------------------------- | -------------------------------------------------------- |
| **S1 기회 발굴**       | "회의 데이터에서 사업 아이디어 찾아줘"  | 반복된 pain point → 기회 후보 테이블 + 첫 검증 실험      |
| **S2 전략 옵션**       | "유료화 전략 짜줘"                      | 본인의 실제 프레임에서 출발한 옵션 3개 비교 + pre-mortem |
| **S3 설득 전략**       | "투자자 ○○를 설득해야 해"               | 상대의 언어로 번역한 논거 + 예상 반론·응답               |
| **S4 정렬 리포트**     | "조직 정렬 상태 점검해줘"               | 대립(tension)별 상태·방치 비용·개입 제안                 |
| **S5 결정 시뮬레이션** | "이 결정하면 리더들이 어떻게 반응할까?" | 인물별 예상 반응(각자의 모델 근거)                       |

> 전략 산출물에는 항상 정직성 각주가 붙습니다: _데이터는 "사람들이 말한 것"을 보여줄 뿐 시장의 진실이 아닙니다 — 아이디어마다 가장 싼 실전 검증 방법을 함께 제안합니다._

## 📅 캘린더 연동 (선택) — 그 자리가 무슨 자리였는지

녹음은 "언제 몇 분"만 압니다. 캘린더는 **무슨 자리였는지**를 압니다. 연결하면
(`"캘린더 연결해줘"`) 세 가지가 추론에서 사실로 바뀝니다:

- **참석자 명단 = 화자 정답지** — "Speaker 2가 누구지"를 추측할 필요가 없습니다. 목소리 지문과 합치면 화자 질문이 거의 사라집니다.
- **TPO가 발언의 무게를 바꿉니다** — 같은 말도 임원 회의와 저녁 식사 자리에서 다릅니다. 식사 자리에서만 나온 신념은 근거 등급 `mid` 상한, IR 자리 발언은 "연출된 말"로 구분합니다. 자리가 근거의 일부입니다.
- **제목·분류** — Plaud의 "2026-07-10 16:15:15" 대신 실제 안건명.

일정은 `_meta/calendar/`에 **로컬 캐시**로만 저장되고, 매칭은 시간 겹침으로 계산됩니다.
사람이 정한 제목·분류는 절대 덮어쓰지 않고, 애매한 건은 확정하지 않고 물어봅니다.

## 🔒 프라이버시 · 매너 / Privacy & etiquette

- **녹음의 적법성은 사용자 책임입니다** (법률 자문 아님): 관할마다 다릅니다 — 예컨대 한국은 본인이 참여한 대화의 녹음은 일반적으로 허용되지만 **제3자 간 대화 녹음은 불법**이고, 미국 일부 주(캘리포니아 등)는 **모든 당사자의 동의**를 요구합니다. 해외 미팅이 많다면 사용 전에 해당 관할의 규정을 확인하세요.
- **로컬 우선**: 코퍼스·DB·뷰어 모두 내 컴퓨터에만. 외부 전송 없음. 민감하면 Whisper 로컬 전사로 녹음도 밖에 안 나갑니다.
- **개인 신상 마스킹**: 지분율·금액·건강·법적 사안은 산출물에서 자동 제외.
- **분석 티 내지 않기**: 방법론 원안자의 조언 — 분석 대상에게 "분석당한다"는 인상을 주지 마세요. 이건 리더 본인의 사적 판단 보조 도구입니다.
- **정직한 근거**: 실제 발언(verbatim)이 있으면 근거 등급이 올라가고, 없으면 "추정"으로 표기합니다. 믿음의 **주체(holder)와 대상(about)을 구분**해서 — "A가 경쟁사 B에 대해 한 말"이 B의 견해로 둔갑하지 않습니다. 조직에 대한 제3자 추정은 등급 상한이 `mid`입니다.
- **검증 내장**: 온톨로지가 갱신될 때마다 `validate.py`가 참조 무결성·근거 규칙·화자 조인 커버리지를 검사하고, 빠진 데이터(파싱 실패·중복 녹음)를 숨기지 않고 보고합니다.

## 💡 팁 / Tips

- 회의록 요약본보다 **원문 녹취**를 넣을수록 정확해집니다.
- 정기 회의를 꾸준히 축적하면 팀 전원의 사고 지도 + 변화 추적이 가능해집니다.
- 투자자·파트너 미팅에도 그대로 — 상대 프레임을 미리 지도로 그려두면 소통이 쉬워집니다.
- 코퍼스를 **Obsidian 볼트**에 두면 회의록을 위키처럼 브라우징할 수 있습니다.

## ❓ FAQ

- **Plaud가 아닌 다른 녹음기여도 되나요?** — 네. 오디오 파일을 주면 Whisper로 로컬 전사합니다(`scripts/whisper_transcribe.py --audio`). Plaud MCP는 자동 수집이 편해질 뿐입니다.
- **매번 "이 사람 누구야?" 물어보나요?** — 처음 한 번만. 오디오 녹음은 로컬 화자 분리 후 **목소리 지문**(`_meta/voiceprints.json`)과 대조해, 이미 확인된 사람은 자동으로 이름이 붙습니다. 확신이 없으면 점수를 보여주고 물어보지, 짐작으로 붙이지 않습니다. 목소리 데이터는 생체정보 — 전부 로컬에 있고 `purge_person.py`나 `voiceprint.py … forget`으로 지웁니다.
- **영어 회의도 되나요?** — 됩니다. 전사 언어 옵션(`--lang en`)과 온톨로지 추출 모두 다국어.
- **DB는 뭘로 보나요?** — 그냥 Claude에게 물으면 됩니다. 직접 보려면 `sqlite3 ontology.db` 또는 아무 SQLite 뷰어.
- **팀원과 공유해도 되나요?** — 데이터는 민감합니다. 공유 전 반드시 내용 검토를 — 기본은 본인 전용.
- **포크해서 고쳐 쓰고 싶어요.** — [CLAUDE.md](./CLAUDE.md)부터 읽으세요(구조·명령·파생 체인·함정).
  스크립트는 표준 라이브러리만 쓰고 `python3 tests/run_tests.py` 하나로 전부 검증됩니다.
  기억할 것 하나: **`objects.json`이 원본이고 뷰어·DB·도시에는 파생물**이라, 편집 후에는
  파생 체인을 순서대로 다시 돌려야 합니다(`stages/ontology.md`에 명시).
- **왜 이렇게 "모른다"고 자주 말하나요?** — 의도적입니다. 이 도구의 유일한 자산은 신뢰이고,
  한 번 지어내면 나머지 전부를 의심하게 됩니다. 확신 없는 것은 추정이라 적고, 의도 추정은
  적중률까지 공개합니다.
